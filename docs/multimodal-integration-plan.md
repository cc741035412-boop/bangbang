## 一、为什么不能直接接（先过这道闸）

交接文档第 10 条铁律：

> 幼儿影像上传外部服务器的合规性尚未闭环。在 dawei 明确说闭环之前，AI 相关能力保持 mock，不要接任何公网大模型。

接多模态模型 = 把幼儿的照片/视频发到第三方大模型服务器。这属于"幼儿影像上传外部服务器"，
需要你先确认合规闭环：

- 家长是否已授权园所将幼儿影像用于 AI 处理（口头/纸质/入园协议条款）；
- 影像在第三方服务器上是否留存、留存多久（多数 API 默认不留存，需确认）；
- 园所/公司是否接受数据出境（国内模型走国内服务器，无出境问题）。

**你的选项：**
1. **demo 阶段豁免**：只在本地 demo 用模拟素材接真实模型，不上真实幼儿影像（代价：验证不了真实效果，但零合规风险）——推荐先用这个。
2. **正式闭环**：补家长授权与数据协议后，真实素材上线（代价：需要你协调园所和法务，周期较长）。

## 三、接完之后怎么改（不改产品架构，只换"眼睛"）

现有流程完全不动，只把"AI 看到什么"从 mock 换成真实视觉理解：

```
素材（照片/视频）
  → 预处理：视频取 3 帧（首/中/尾）+ 音频转写保留（产品调研 E2 结论：必须保留教师原话）
  → 多模态模型：输出"画面里发生了什么"的结构化客观描述
  → 送入现有工作流 A（白描）→ 教师确认闭环（不变）
```

原则保持不变：
- 系统纯计算（时长分层等）零幻觉，不交给模型；
- `is_mock` / notice 提示、`ai_run` 审计记录继续保留，方便对比 mock 与真实模型的效果；
- 教师对指标、分析、最终记录负责。

## 四、测试计划（接入后）

1. mock 模式全量回归（现有 27 个后端测试 + 前端 26 个测试）；
2. 虚构素材端到端：上传模拟图片/视频 → 真实模型白描 → 确认闭环；
3. 效果对比：同一批虚构素材，mock vs 真实模型的白描可用率、指标采纳率（复用现有埋点）。
