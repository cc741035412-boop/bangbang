## 0. 怎么开一个功能

所有能力开关集中在 `frontend/src/config/features.ts`：

```ts
export const FEATURES = {
  auth: false,              // 登录 / 退出 / 账号与安全
  kindergarten: false,      // 园所与班级管理
  exportDocx: true,         // 已通
  exportPdf: false,
  exportMarkdown: false,
  exportHistory: false,
  childProfile: false,      // 幼儿档案详情
  childMutation: false,     // 新增 / 删除幼儿
  multiChildCapture: false, // 一条素材关联多个幼儿
};
```

**后端做好一个，把对应的 `false` 改成 `true`，界面自动放开，不要改 UI 代码。**

为 false 时的行为已经写好了，三种情况：

| 情况 | 表现 |
|---|---|
| 独立页面（账号、园所、导出记录、幼儿管理、档案详情） | 页面自身 `Navigate` 跳回 `/mine`，同时「我的」页不渲染这个入口 |
| 导出格式（PDF / Markdown） | 卡片置灰 + 「暂未开放」标签，不可选中，不发请求 |
| 登录闸门 | `RequireAuth` 整体放行，现有流程完全不受影响 |

这样做的原因：产品原则是**不做假按钮、不做假数据入口**。宁可入口不出现，也不要点了没反应。

新接口暂时走 `frontend/src/api/http.ts`（手写 fetch 封装），因为 `src/api/generated/schema.d.ts`
是从后端 `openapi.json` 生成的，后端没有的路径写进 `apiClient` 会直接 typecheck 失败。
**接口上线后请跑 `npm run api:generate`，再把调用逐个换成 `apiClient.GET/POST`，然后删掉 `http.ts`。**

鉴权：`http.ts` 会自动从 `localStorage["bangbang.access_token"]` 读 token，
带 `Authorization: Bearer <token>`。401 会自动清 token 并把用户送回 `/login`。

## 1. 登录 / 退出 / 账号与安全 —— `FEATURES.auth`

前端文件：`features/auth/api.ts`、`features/auth/auth-context.tsx`、
`features/auth/auth-context-value.ts`、`pages/login-page.tsx`、`pages/account-page.tsx`

### 数据表

```
accounts
  id            PK
  phone         varchar(11)  UNIQUE NOT NULL
  teacher_id    FK -> teachers.id   NOT NULL   -- 落款、归属都用这个
  created_at    timestamptz
  deleted_at    timestamptz NULL              -- 注销走软删，保留审计线索

sms_codes
  id, phone, code(6), purpose, expires_at, consumed_at, created_at
```

`purpose` 至少要区分 `login` / `change_phone` / `delete_account`，
否则登录用的验证码可以拿来注销账号。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/code` | 发验证码 |
| POST | `/api/auth/login` | 手机号 + 验证码登录；号码不存在时返回 404，前端引导去注册 |
| POST | `/api/auth/register` | 注册，同时建 teacher / kindergarten / classroom |
| GET | `/api/auth/me` | 当前账号；未登录返回 401（前端把 401 当正常状态处理，不弹错） |
| POST | `/api/auth/logout` | 让 token 失效 |
| PATCH | `/api/auth/phone` | 换绑手机号，验证码发到**新号** |
| DELETE | `/api/auth/account` | 注销，需验证码 |

**POST /auth/code**
```json
请求 { "phone": "13812345678" }
响应 { "expires_in": 300, "cooldown_sec": 60 }
```
同一号码 60 秒内重复请求返回 429。前端已有 60 秒倒计时，但不能只靠前端挡。

**POST /auth/login**
```json
请求 { "phone": "13812345678", "code": "462913" }
响应 200 {
  "access_token": "...",
  "token_type": "bearer",
  "expires_in": 2592000,
  "account": { AuthAccount }
}
```

**AuthAccount**（`GET /auth/me` 返回同一结构）
```json
{
  "id": 1,
  "phone": "13812345678",
  "teacher_id": 1,
  "name": "李老师",
  "kindergarten_id": 1,
  "kindergarten_name": "阳光第一幼儿园",
  "classroom_id": 1,
  "classroom_name": "中一班",
  "created_at": "2026-08-27T01:40:00Z"
}
```

**POST /auth/register**
```json
请求 {
  "phone": "13812345678", "code": "462913",
  "name": "李老师",
  "kindergarten_name": "阳光第一幼儿园",
  "classroom_name": "中一班"
}
```
园所名已存在时不要自动并入已有园所——同名幼儿园很多，误并会让两个园看到彼此的幼儿数据。
建议：新建独立园所，把并园留给后面的「加入园所」功能。注册者在新园里 `role = owner`。

**DELETE /auth/account**：请求体 `{ "code": "..." }`。
账号软删，同时删除该教师名下的素材文件与观察记录（前端在页面上明确写了这一点）。

### 错误约定（所有新接口通用）

非 2xx 时返回 `{ "detail": "给老师看的一句话" }`。
前端会直接把 `detail` 原样显示，所以**请写成老师能看懂的中文**，不要返回 `ValidationError` 之类的英文。

## 2. 园所与班级 —— `FEATURES.kindergarten`

前端文件：`features/kindergarten/api.ts`、`pages/kindergarten-page.tsx`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/kindergartens/current` | 当前教师所在园所全量信息 |
| PATCH | `/api/kindergartens/current` | 改园所名，仅 owner |
| POST | `/api/classrooms` | 新增班级，仅 owner |
| PATCH | `/api/classrooms/{id}` | 改班级名，仅 owner |
| DELETE | `/api/classrooms/{id}` | 删班级，仅 owner |

**GET /kindergartens/current**
```json
{
  "id": 1,
  "name": "阳光第一幼儿园",
  "classrooms": [{ "id": 1, "name": "中一班", "child_count": 24 }],
  "teachers": [{ "id": 1, "name": "李老师", "phone": "138****6621",
                 "classroom_id": 1, "role": "owner" }],
  "my_role": "owner"
}
```

`child_count` 由后端聚合，前端不自己数。
`teachers[].phone` 请后端就打好码再返回，别把同事的完整手机号发到前端。

**DELETE /classrooms/{id}**：班里还有幼儿时返回 **409**，
`detail` 写清楚还剩几名，例如「中一班还有 24 名幼儿，请先移出或删除后再删班级」。
前端会原样展示这句话。**不要提供「连同幼儿一起删」的参数**——那是误删数据最常见的来源。

非 owner 调用写接口一律 403。

## 3. PDF / Markdown 导出 —— `FEATURES.exportPdf` / `exportMarkdown`

前端文件：`features/exports/api.ts`、`components/export-format-sheet.tsx`，
`pages/observation-detail-page.tsx` 已改成格式无关。

现有接口加一个查询参数即可，**docx 的行为保持不变**：

```
GET /api/observations/{obs_id}/export?include_indicators=true&format=docx|pdf|md
GET /api/exports/monthly?year=2026&month=8&include_indicators=true&format=docx|pdf|md
```

- `format` 缺省为 `docx`，保证老客户端不受影响
- Content-Type：`application/vnd.openxmlformats-officedocument.wordprocessingml.document` /
  `application/pdf` / `text/markdown; charset=utf-8`
- 文件名统一 `{幼儿姓名}_观察记录_{YYYYMMDD}.{ext}`，
  放在 `Content-Disposition` 里，**必须带 `filename*=UTF-8''` 版本**，
  否则中文名在部分浏览器会变乱码（前端 `fileNameFromResponse` 优先读这个字段）
- 三种格式的正文内容必须一致：标题 → 基本信息 → 观察目的 → 观察记录 →
  观察分析（只含 `accepted = true` 的指标）→ 下一步支持策略 → 落款
- PDF 建议由 docx 渲染而来或共用同一套模板，不要单独维护一份排版，否则两份会漂

## 4. 导出历史 —— `FEATURES.exportHistory`

前端文件：`features/exports/api.ts`、`pages/export-history-page.tsx`

### 数据表

```
export_records
  id           PK
  account_id   FK
  observation_id FK NULL          -- 整月导出时为 NULL
  scope        enum('single','monthly')
  format       enum('docx','pdf','md')
  file_name    text
  size         int
  child_name   text NULL          -- 冗余存一份，幼儿删了历史仍可读
  storage_key  text NULL          -- 保留文件时填，不保留就为 NULL
  created_at   timestamptz
```

**记录时机：文件成功生成并开始返回之后写一条，前端不上报。**
前端上报的话，下载中断也会留下一条"成功"记录。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/exports/history` | 当前账号的导出记录，按 `created_at` 倒序 |

```json
[{
  "id": 1, "observation_id": 12, "scope": "single", "format": "docx",
  "file_name": "朵朵_观察记录_20260826.docx", "size": 43008,
  "child_name": "朵朵", "created_at": "2026-08-26T09:20:00Z",
  "download_url": "/api/exports/history/1/file"
}]
```

`download_url` 为 `null` 时，前端自动把按钮换成「重新导出」跳回那篇记录。
所以**不保留历史文件也是可接受的实现**，先上线列表即可。

## 5. 幼儿档案详情 —— `FEATURES.childProfile`

前端文件：`features/children/api.ts`、`pages/child-profile-page.tsx`

| 方法 | 路径 |
|---|---|
| GET | `/api/children/{child_id}/profile` |

```json
{
  "id": 1, "name": "朵朵",
  "classroom_id": 1, "classroom_name": "中一班",
  "birth_date": "2021-05-06", "gender": "female",
  "created_at": "2026-03-01T00:00:00Z",
  "media_count": 8,
  "record_count": 3,
  "observed_day_count": 4,
  "dimension_counts": { "身体参与": 2, "社会互动": 2 },
  "records": [{
    "observation_id": 12,
    "title": "搭高与分工",
    "area_name": "建构区",
    "observed_at": "2026-08-26T01:40:00Z",
    "dimensions": ["身体参与", "社会互动"],
    "exported": true
  }]
}
```

统计口径：
- `media_count`：该幼儿名下所有素材，含还没生成记录的
- `record_count` / `records`：只算 `status = confirmed` 的记录，按 `observed_at` 倒序
- `observed_day_count`：有素材或有记录的自然天数去重
- `dimension_counts`：只统计 `accepted = true` 的指标所属维度，**首期只有「身体参与」「社会互动」两个维度**

> ⚠️ `dimension_counts` 是「这个维度被观察到几次」，不是孩子的水平。
> **后端不要返回任何评级、评分、百分位、同班对比。**
> 页面上固定写着一句「只统计这个维度被观察到几次，不代表孩子在这方面的水平」——
> 一旦返回了可比较的数值，这句话就挡不住它被当成评分表用。

## 6. 新增 / 删除幼儿 —— `FEATURES.childMutation`

前端文件：`features/children/api.ts`、`pages/children-manage-page.tsx`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/children` | 新增，请求 `{ name, classroom_id?, birth_date?, gender? }`，响应 `{ id, name }` |
| DELETE | `/api/children/{child_id}` | 删除 |

删除时若名下还有素材或观察记录，返回 **409**，
`detail` 例如「朵朵名下还有 8 条素材、3 篇记录，请先处理后再删除」。
同样**不提供级联删除参数**。前端已经做了二次确认面板，并会原样展示这句 `detail`。

`PATCH /children/{child_id}` 已存在，不用动。

## 7. 多幼儿关联上传 —— `FEATURES.multiChildCapture`

前端文件：`features/observations/api.ts` 的 `submitCapture`、`components/upload-sheet.tsx`

### 数据表

```
observation_children
  observation_id FK
  child_id       FK
  PRIMARY KEY (observation_id, child_id)
```

`observations.child_id` **保留不动**，表示这条记录的主角（落款、文件名、档案归属都用它）。
关联表用于「这段视频里还出现了谁」。

| 方法 | 路径 |
|---|---|
| PUT | `/api/observations/{obs_id}/children` |

```json
请求 { "child_ids": [1, 3, 5] }   // 第一个是主角，后端据此同步 observations.child_id
响应 200 { "child_ids": [1, 3, 5] }
```

用 PUT 全量覆盖，不用 POST 增量——老师在整理页反复改的时候，全量语义不会残留脏数据。

前端行为：上传时先按原流程建记录（`child_id` = 主角），**成功之后**再补一次这个请求。
这一步失败**不回滚整条记录**，只提示「其他幼儿没有关联上，可以在整理页再补选」——
素材已经传上去了，让老师重新上传一遍视频代价太大。

档案页的 `media_count` / `record_count` 请按关联表统计（主角 + 关联），
否则多人游戏的素材只会算在主角一个人头上。

## 8. 验收清单

后端每做完一项，翻开关 → 跑 `npm run typecheck && npm run lint && npm test` → 手点一遍：

- [ ] `auth`：注册 → 自动登录 → 刷新仍在登录态 → 退出 → 被挡回 `/login` → 重新登录
- [ ] `auth`：换绑手机号后 `/auth/me` 返回新号；注销后 token 立即失效
- [ ] `kindergarten`：非 owner 看不到编辑按钮，直接调写接口返回 403
- [ ] `kindergarten`：删有幼儿的班级 → 409，页面显示后端那句话
- [ ] `exportPdf` / `exportMarkdown`：三种格式正文一致，中文文件名不乱码
- [ ] `exportHistory`：导出一次后列表里多一条，字段齐全
- [ ] `childProfile`：`dimension_counts` 只有两个维度，没有任何评分字段
- [ ] `childMutation`：删有记录的幼儿 → 409
- [ ] `multiChildCapture`：选三个孩子上传，三个人的档案里都能看到这条素材
